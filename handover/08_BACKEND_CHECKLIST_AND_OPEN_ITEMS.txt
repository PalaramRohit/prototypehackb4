3. KNOWN LIMITATIONS / TECH DEBT IN THE FRONTEND  (FYI, not blockers)
--------------------------------------------------------------------------------

  - Push opt-in sends a fake token (file 07 section 5). Needs joint work.
  - No pagination: /events must return everything. Fine up to ~100 events.
  - Event search is client-side over the loaded list only.
  - "N TEAMS LOOKING FOR MEMBERS" on Home counts the items returned by
    /team-openings?limit=3, so it never shows more than 3. If you want the
    real total, we could add a count to /stats (e.g. open_teams) - frontend
    change needed.
  - No CAPTCHA / honeypot on public forms - rely on server rate limiting for
    now; add a CAPTCHA later if spam appears.
  - SEO tags are set client-side; per-event link previews on WhatsApp /
    LinkedIn show the default site preview (file 06, section 3).
  - sitemap.xml is static and doesn't list event pages.
  - No ad impression/click tracking (file 07 section 6).
  - ErrorBoundary logs to console only; hook up Sentry or similar if wanted
    (src/app/ErrorBoundary.tsx, componentDidCatch).
  - The spec asked for Next.js; the frontend is Vite + React SPA
    (file 01 section 1). No server routes in this repo.
